# stack-parser-generator-utils

This project contains a bespoke LALR parser generator as well as various
configurations/grammars for it. The parsers generated by this toolset
are meant for use with [STACK](https://stack-assessment.org/), in STACK, and
in particular tools built to manage materials.

This toolset only produces the LALR tables with certain operator precedence
assumptions and fills in some templates to produce source code for the parser.
Lexers/tokenisers are not included in this project.

The templates for parser logic tend to include fall-back logic for attempting
insertion of implied multiplication signs, otherwise they are normal
LALR parsers.

## For who?

This toolset is for those updating the STACK grammar and parser, and for those
wishing to generate matching parsers for other programming languages.


## How to use?

If you do not modify anything then the `output` has the products, this
repository always includes the results from the latest versions execution.

Otherwise, you will need Rust and 
[cargo](https://doc.rust-lang.org/cargo/getting-started/installation.html).
Once you have those executing `cargo run` in the root of the repository will
generate the `output` directory and its contents.

To modify what to generate one can define tasks in `configs/tasks.json`, each
task defines which grammar it uses and if the grammar is to be modified, it
then defines which templates are to be populated using whatever things are
constructed in the `src/main.rs` logic.

In general, use the `configs/full-STACK-maxima.json` grammar and apply
modifications in the style of the `configs/mods-lite.json` example where
we simply drop all the control flow features out to produce a simpler version. 
Basically, don't create a full new grammar, create a diff so that other bits
can be shared.

### Example: adding operators

Should you wish to add a new operator to the parser, do as follows:

 1. Add a new section to `configs/full-STACK-maxima.json`.
 2. Check the operator precedence section of the `src/main.rs`, maybe
    you need to add it there if you want to produce the correct
    order of operations tree.
 3. Try generating the parsers with `cargo run`. If no `shift/reduce` errors
    appear, things should be fine.
 4. Then remember to add that new operator as a keyword/symbol in your lexers
    as well.


## Current outputs

Currently the generator outputs two different products:

 1. The Rust version of the parser published as the crate called 
    [`stack_maxima_parser`](https://crates.io/crates/stack_maxima_parser).
 2. The PHP version intended to be used inside STACK.

In the future a JS/TS version is probably going to be added.
